# CPU Professional-Master Thesis Compliance Checklist

Use this checklist when the task is a **China Pharmaceutical University professional-master's thesis** and school-format compliance must be checked before AWAS claims the output is ready.

## 1. Route and authority

- [ ] This is really the **CPU professional-master** route, not the `同等学历` route.
- [ ] If local files conflict, `<PRIVATE_WORKSPACE>\参考\论文格式.doc` is being treated as the controlling authority.
- [ ] Older official files and school templates are being used as supporting references only when they do not conflict with the controlling local authority file.

## 2. Package state

- [ ] The current package state is explicit: `blind-review package` or `final archive package`.
- [ ] The workflow is not silently mixing blind-review requirements with final-archive requirements.
- [ ] If the package is for blind review, the reduced review-package logic is being used where the high-priority local file requires it.

## 3. Front matter

- [ ] Cover follows the CPU professional-master route rather than the same-equivalent route.
- [ ] Originality statement is present if required for the current package state.
- [ ] Copyright authorization is present if required for the current package state.
- [ ] Table of contents is present and placed correctly.
- [ ] Chinese abstract is present.
- [ ] English abstract is present.
- [ ] Abbreviation / symbol list is included or intentionally omitted with a clear reason.
- [ ] Publication list during degree period is included when the package requires it.
- [ ] Acknowledgements are included when the package requires them.

## 4. AI-assisted research and writing commitment

- [ ] The `人工智能技术辅助研究与写作承诺书` has been considered explicitly.
- [ ] If the current rule set requires it, it is included as a formal front-matter item.
- [ ] Its presence or omission is consistent with the current package state.
- [ ] Pagination exclusions have been adjusted accordingly.

## 5. Pagination and layout

- [ ] Paper size is A4.
- [ ] Body line spacing is 20 pt fixed unless a stricter local rule overrides it.
- [ ] Formula spacing is handled separately where required.
- [ ] Margins follow the school-side constraints.
- [ ] Header content matches odd/even page rules.
- [ ] Header separator line is present where required.
- [ ] Front matter uses Roman numerals where required.
- [ ] Body and later sections use Arabic numerals where required.

## 6. Typography

- [ ] Chapter titles follow the current school-side font and alignment requirements.
- [ ] Section and lower-level headings follow the school-side font and alignment requirements.
- [ ] Body text follows the school-side font and size requirements.
- [ ] References follow the school-side font and indentation requirements.
- [ ] Letters and numbers are handled consistently.

## 7. Body structure

- [ ] The chapter being written has a clear thesis-level chapter job.
- [ ] The writing is thesis-oriented rather than paper-oriented.
- [ ] Cross-chapter transitions are explicit where needed.
- [ ] Journal-style compactness is not overriding school-format readability.

## 8. Tables and figures

- [ ] Tables follow the CPU three-line-table convention.
- [ ] Table numbering is chapter-based.
- [ ] Table titles are placed above the table.
- [ ] Figure numbering is chapter-based.
- [ ] Figure titles/captions are placed below the figure.
- [ ] Figure captions explain statistical methods and all symbols/markers when required.
- [ ] Figure quality, resolution, and width suitability are acceptable for school output.

## 9. References

- [ ] Reference style follows the thesis-side local rule before any journal habit.
- [ ] Where older files conflict, GB/T 7714-2015 has been prioritized if the higher-priority local authority points to it.
- [ ] Page ranges are complete.
- [ ] Author truncation rules are correct.
- [ ] In-text citation style matches the school-side expectation.

## 10. Thesis-to-paper boundary

- [ ] The current task is still being treated as thesis work, not silently converted into paper work.
- [ ] If a paper-style output is desired, it is explicitly marked as a second-stage conversion.

## Final gate

AWAS should not call the output `CPU-compliant` until every unchecked item above is either:

- completed, or
- intentionally marked `not applicable` with a reason tied to the current package state.
