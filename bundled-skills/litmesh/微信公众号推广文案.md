# LitMesh：一张「文献网」，搜遍全球学术库，零密钥开箱即用

> 免 API Key · 多源聚合 · 自动引文 · 跨智能体 CLI
> 写给每一个被文献检索折磨过的研究者。

---

## 一、背景：我们为什么还需要一个文献工具？

开题、综述、实验设计、写讨论……科研的第一步永远是**找文献**。

但现实是：

- 想查全，要在 **PubMed、Semantic Scholar、arXiv、Google Scholar、bioRxiv、DOI** 之间反复横跳；
- 想引用规范，要手动去核对作者、年份、期刊、DOI，再一行行排 IEEE / APA / BibTeX；
- 想接入 AI 智能体（WorkBuddy、Claude Code、Codex），又卡在**各种 API Key、各种配置、各种不兼容**。

有没有一种可能：**不用任何密钥，一条命令，把这些学术库全部打通，还能自动生成引用？**

**LitMesh** 就是为此而生的。

---

## 二、LitMesh 是什么？

**LitMesh = Literature（文献）+ Mesh（网）**。

它把多个学术数据库的检索与引用能力，聚合成「一张网」，再用**一个免 API Key 的命令行工具箱**统一调用。

- 默认 **direct 模式**直连免费公共 API，**不需要任何 API Key** 即可使用全部 36 个工具；
- 同一份核心代码，能在 **WorkBuddy / Claude Code / Codex** 三种智能体环境里独立运行；
- 配置**只走环境变量**，三个环境互不冲突、可各自自定义。

> **关于来历**：LitMesh 是一个**独立项目**，设计实现上参考了学术检索相关的公开资料与开源项目（如 `dsh-ai4scholar`，MIT License）。其核心定位为「免 API Key 服务是安装前提」——默认直连免费公共 API，提供 36 个学术检索与引文工具。参考项目中需要计费的 `sci_draw` 与额度查询（proxy 模式）不在 LitMesh 范围内。

## 三、核心功能（6 个你一定会用到的能力）

**1. 多源聚合检索（Mesh）**
一次调用跨 Semantic Scholar、PubMed、OpenAlex（Google Scholar）、arXiv、bioRxiv / medRxiv、DOI；`search_papers` 还能统一跨平台检索并自动合并去重。

**2. 自动引文 auto_cite**
把一段正文「贴进去」，它在本地完成：断句 → 真实检索 → 插入编号标注 → 生成 **IEEE 参考文献 + BibTeX**。写综述、填参考文献不再手抖。

**3. 引文脉络**
任意一篇论文，一键拿到它的**参考文献**与**被引文献**（`get_semantic_references` / `get_semantic_citations` / `get_pubmed_related`），顺藤摸瓜找全相关研究。

**4. 全文抽取**
arXiv / Semantic Scholar / bioRxiv / medRxiv / DOI 全文，`read_*_paper` / `read_by_doi` 直接把 PDF 文本抽出来，便于精读与二次处理。

**5. 作者与期刊画像**
`search_semantic_authors` / `get_semantic_author_papers` 查某位学者全部论文；`search_semantic_bulk` 批量检索，适合做文献计量。

**6. 环境无关、可移植、可分享**
核心就是一个 `litmesh.mjs` + 编译好的 `lib/`，不依赖 TypeScript 工具链，拷贝到任意环境 `npm install` 即可用。

## 四、怎么装？三步，零门槛

**前置**：Node.js ≥ 22.19（WorkBuddy 自带；Claude Code / Codex 用系统 Node 即可）。

```bash
git clone <your-repo>/litmesh.git
cd litmesh
npm install
```

然后按需「放」到对应环境：

```bash
# WorkBuddy
cp -r "$(pwd)" "$HOME/.workbuddy/skills/litmesh"

# Claude Code
cp -r "$(pwd)" "$HOME/.claude/skills/litmesh"

# Codex：在本目录直接运行 codex 即可（读取 codex.md）
```

装好后在对话里直接说需求，例如：「用 LitMesh 检索最近关于 graph neural network 的 PubMed 论文」，智能体会自动调用：

```bash
node litmesh.mjs search_pubmed '{"query":"CRNA anesthesia outcomes","max_results":3}' --render
```

## 五、可复现案例（真实运行，非演示数据）

下面每一个结果都来自 `npm install` 之后的真实网络调用。

**案例 A · PubMed 检索（渲染 Markdown）**

```bash
node litmesh.mjs search_pubmed '{"query":"CRNA anesthesia outcomes","max_results":3}' --render
```

输出（节选）：

```
PubMed results for "CRNA anesthesia outcomes" (showing 3 of 141):

1. **[Retire the Conventional Laryngoscope?](https://pubmed.ncbi.nlm.nih.gov/36722782/)**
   Christopher Bailey, Rhys Dela Cruz, Shari Burns et al. · 2023 · AANA journal
   PMID: 36722782
   ...
```

**案例 B · 自动引文 auto_cite**

贴一段文字，返回带 `[1][2][3]` 标注的正文 + IEEE 参考文献 + BibTeX：

```json
{
  "annotatedText": "Attention mechanisms ... [1] The Transformer architecture introduced by Vaswani et al. [2] ... [3]",
  "references": [
    { "number": 2, "formatted": "[2] S. Zheng et al., \"Rethinking Semantic Segmentation ... with Transformers,\" 2021. doi: 10.1109/cvpr46437.2021.00681." }
  ],
  "bibtex": "@article{ref2,\n  title = {Rethinking Semantic Segmentation ...}\n  ...\n}"
}
```

**案例 C · 统一跨平台检索 search_papers（优雅降级）**

当 Semantic Scholar 匿名限流（HTTP 429）时，工具**不中断**，自动保留 PubMed / arXiv 结果并附 warning——这就是「稳定可重现」的底气：

```json
{
  "perSource": [
    { "source": "semantic-scholar", "count": 0, "error": "HTTP 429: Too Many Requests ..." },
    { "source": "pubmed", "count": 10, "total": 13689 },
    { "source": "arxiv", "count": 10, "total": 485822 }
  ],
  "warning": "Semantic Scholar: ... HTTP 429 ..."
}
```

> 想完全无警告？把 `sources` 设为 `["pubmed","arxiv"]` 即可；或设置 `SEMANTIC_SCHOLAR_API_KEY` 提升 Semantic Scholar 额度。

## 六、实用价值：谁该用，用在哪？

- **研究生 / 青年教师**：开题调研、综述写作、参考文献格式化，效率翻倍。
- **AI 智能体开发者**：把 36 个学术工具一次性接入自己的 Agent，无需逐个对接各平台 API。
- **文献计量 / 科研评价**：批量检索、作者画像、引文网络，开箱即用。
- **教学与科普**：让学生专注「读文献」本身，而不是被检索门槛劝退。

它最打动人的一点是：**把「学术检索能力」从「配 Key、调接口、写爬虫」里解放出来**，变成一句 `node litmesh.mjs <工具> '<参数>'`。

## 七、获取方式与说明

- **开源协议**：MIT（保留所参考项目 `dsh-ai4scholar` 版权声明）。
- **仓库内容**：`litmesh.mjs`（核心适配器）、`lib/`（运行时）、`SKILL.md` / `codex.md`（三环境接入）、`references/api-cheatsheet.md`（36 工具参数速查）、`examples/cases.md`（可复现案例）。
- **范围说明**：LitMesh 只覆盖**免 Key 的 direct 模式**（36 个工具）；参考项目需计费的 `sci_draw` 与额度查询不在其内。
- **已知限制**：Semantic Scholar 匿名公共接口偶发 429 限流，稍后重试或配置可选 Key 即可；`auto_cite` 免 Key 模式用本地关键词匹配，精度低于计费版，但对规范文本已足够好用。
