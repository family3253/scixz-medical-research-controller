# LitMesh 跨平台使用教学案例（WorkBuddy / Claude Code / Codex）

> 本文档面向「学习者 / 复现者」，给出在 **三个主流 Agent 平台** 中安装、调用 LitMesh 的
> **具体命令与可直接复制的提示词（prompt）**，以及 5 个可稳定复现的实操案例。
>
> 核心前提：LitMesh 默认 `direct` 模式，**免 API Key**，真实访问公共学术接口。
> 通用 CLI 入口：`node litmesh.mjs <tool> '<json参数>' [--render]`。
> 全量工具以 `node litmesh.mjs --list` 为准（共 **36** 个，见文末附录）。

---

## 一、前置条件（三平台一致）

| 项目 | 要求 |
| --- | --- |
| 运行时 | Node.js **≥ 22.19.0**（推荐 WorkBuddy 内置 22.22.2） |
| 网络 | 可访问 `api.semanticscholar.org` / `eutils.ncbi.nlm.nih.gov` / `export.arxiv.org` / `api.openalex.org` |
| 密钥 | **无需任何 Key**（`direct` 模式）。可选设 `SEMANTIC_SCHOLAR_API_KEY` 提高匿名限流额度 |
| 仓库 | 已 `git clone` 或下载 `litmesh/` 目录，内含有 `lib/`、`litmesh.mjs`、`package.json` |

> 说明：三个平台**共用同一份 `litmesh/` 目录与同一个 CLI 适配器**，区别只在“把目录放到哪里”和“用哪种提示词触发”。配置**只走环境变量**，三者各自设置、互不冲突。

## 二、安装步骤（按平台复制命令）

### 2.1 WorkBuddy（已为你装好，可跳过；新机器照做）

```bash
# Windows（PowerShell / Git Bash 均可；以下用 Git Bash 路径写法）
SKILL_DIR="$HOME/.workbuddy/skills/litmesh"
cp -r "/f/Case/tmp/ai4scholar-plugin-dsh-main/litmesh" "$SKILL_DIR"
cd "$SKILL_DIR" && npm install

# 验证安装：应输出 36 个工具名
node litmesh.mjs --list | wc -l
```

> 安装后**无需重启**：WorkBuddy 在下次对话自动识别 `litmesh` 技能（SKILL.md 含 `agent_created: true`）。

### 2.2 Claude Code

```bash
SKILL_DIR="$HOME/.claude/skills/litmesh"
mkdir -p "$SKILL_DIR"
cp -r "/f/Case/tmp/ai4scholar-plugin-dsh-main/litmesh/." "$SKILL_DIR/"
cd "$SKILL_DIR" && npm install

# 验证
node litmesh.mjs --list | wc -l
```

可选：在项目或全局 `CLAUDE.md` 加一句话，让 Claude 更主动调用：

```markdown
## LitMesh 学术检索技能
安装位置：~/.claude/skills/litmesh
需要时运行 `node ~/.claude/skills/litmesh/litmesh.mjs <tool> '<json>' [--render]`。
支持 PubMed / arXiv / Semantic Scholar / OpenAlex / DOI / bioRxiv / medRxiv 检索与 auto_cite 自动引文。
```

### 2.3 Codex

Codex 读取仓库内的 `codex.md` 作为项目指令。两种用法：

**方式 A（推荐，零配置）**：直接在 `litmesh/` 目录内启动 Codex，它会自动加载 `codex.md`。

```bash
cd "/f/Case/tmp/ai4scholar-plugin-dsh-main/litmesh"
npm install
codex        # 启动后输入任务，Codex 会自行运行 litmesh.mjs
```

**方式 B（全局常驻）**：把 `codex.md` 软链/复制到 `~/.codex/codex.md`，任意目录都能用。

```bash
mkdir -p "$HOME/.codex"
cp "/f/Case/tmp/ai4scholar-plugin-dsh-main/litmesh/codex.md" "$HOME/.codex/codex.md"
```

## 三、三个平台的调用方式对比

| 平台 | 触发方式 | 你“说”什么 | 系统实际执行 |
| --- | --- | --- | --- |
| **WorkBuddy** | 自然语言 → 技能路由 | “用 litmesh 检索 PubMed 上…渲染成 Markdown” | Agent 运行 `node .../litmesh.mjs search_pubmed ... --render` |
| **Claude Code** | 自然语言 / 技能 | “帮我用 litmesh 查 arXiv 上 attention 的论文” | Claude 运行同上 CLI |
| **Codex** | 任务式 prompt + shell | “Use litmesh to search arXiv for X and save to out.json” | Codex 在 terminal 执行 `node litmesh.mjs ...` 并读写文件 |

**关键差异**：WorkBuddy / Claude Code 是“对话即调用”；Codex 更偏“把任务交给它、它自己跑命令并落盘文件”。

## 四、平台专属提示词（直接复制即可用）

> 每个提示词都附「等效命令」，方便你确认 Agent 实际在跑什么。

### 4.1 WorkBuddy 提示词（5 条）

**① 检索 PubMed 并渲染**
```
用户提示词：
请用 litmesh 检索 PubMed 上关于 “CRNA anesthesia outcomes” 的论文，
最多 3 篇，渲染成 Markdown 给我。

等效命令：
node litmesh.mjs search_pubmed '{"query":"CRNA anesthesia outcomes","max_results":3}' --render
```

**② 跨平台统一检索**
```
用户提示词：
用 litmesh 在 PubMed、arXiv 和 Semantic Scholar 上检索
“graph neural network”，每个来源 5 条，汇总成 Markdown。

等效命令：
node litmesh.mjs search_papers '{"query":"graph neural network","sources":["semantic-scholar","pubmed","arxiv"],"max_results":5}' --render
```

**③ 自动生成引文（auto_cite）**
```
用户提示词：
下面这段综述里提到了几项研究，请帮我用 litmesh 的 auto_cite 功能
自动标引，按 IEEE 格式输出标注文本、参考文献和 BibTeX：
“Attention mechanisms have become an integral part of compelling
sequence modeling and transduction models in various tasks in recent
years. The Transformer architecture introduced by Vaswani et al. relies
entirely on self-attention and has been shown to be effective for
machine translation.”

等效命令：
node litmesh.mjs auto_cite '{"text":"Attention mechanisms ... machine translation.","style":"ieee"}'
```

**④ 抽取 arXiv 全文**
```
用户提示词：
用 litmesh 下载并抽取 arXiv 论文 2106.15524 的前 2000 字正文，渲染给我。

等效命令：
node litmesh.mjs read_arxiv_paper '{"paper_id":"2106.15524","max_chars":2000}' --render
```

**⑤ 查某作者论文**
```
用户提示词：
用 litmesh 在 Semantic Scholar 上搜索作者 “Yoshua Bengio”，返回前 3 位
作者的主页与论文数。

等效命令：
node litmesh.mjs search_semantic_authors '{"query":"Yoshua Bengio","max_results":3}'
```

### 4.2 Claude Code 提示词（含让 Claude 主动用技能的话术）

```
# 让 Claude 先确认技能可用（首次建议）
“先确认 ~/.claude/skills/litmesh 里的 litmesh 技能能跑起来（node litmesh.mjs --list 应该有 36 个工具），然后帮我做下面的事。”

# 日常任务示例
“用 litmesh 查 PubMed 上最近关于 ‘mRNA vaccine durability’ 的 5 篇论文，
把标题、PMID、摘要首句整理成一个表格，存到 pubmed_results.md。”

# 让 Claude 串联多步（体现跨 Agent 价值）
“用 litmesh 检索 arXiv 上 ‘diffusion model’ 的 10 篇论文，
对每篇用 read_arxiv_paper 抽前 800 字，最后汇总成一份带链接的速览文档。”
```

> 小技巧：Claude Code 里加上 “请用 litmesh 技能（CLI：node .../litmesh.mjs）” 可避免它自己臆造工具名。

### 4.3 Codex 指令（task prompt，偏向“跑命令 + 落盘”）

```
# 直接给 Codex 一个可执行任务（在 litmesh/ 目录启动 codex 后粘贴）
Use the litmesh skill (node litmesh.mjs) to:
1. Search PubMed for "CRNA anesthesia outcomes", max 5 results, render to Markdown.
2. Save the output to pubmed_out.md in this directory.
3. Also run auto_cite on the paragraph below and save to cite_out.json:
   "Attention mechanisms have become an integral part of compelling sequence
    modeling and transduction models in various tasks in recent years."
Report the exact commands you ran and whether each succeeded.

# 批量/工程化任务
Write a small bash loop that, for each id in (2106.15524 2301.00001 2205.12345),
calls `node litmesh.mjs read_arxiv_paper '{"paper_id":"<id>","max_chars":1000}'`
and concatenates the results into arxiv_dump.md. Run it and show me the file.
```

## 五、可复现案例（三平台通用，附真实输出）

> 以下命令在**三个平台安装完成后均可原样复现**。括号内为实测稳定性。

### 案例 1 · PubMed 检索（渲染 Markdown）
```bash
node litmesh.mjs search_pubmed '{"query":"CRNA anesthesia outcomes","max_results":3}' --render
```
真实输出节选：
```
PubMed results for "CRNA anesthesia outcomes" (showing 3 of 141):
1. **[Retire the Conventional Laryngoscope?](https://pubmed.ncbi.nlm.nih.gov/36722782/)**
   Christopher Bailey, Rhys Dela Cruz, Shari Burns et al. · 2023 · AANA journal
   PMID: 36722782
   Video laryngoscopy is useful when direct laryngoscopy fails ...
```
✅ 稳定性**高**（NCBI 公共接口，匿名即用）。

### 案例 2 · arXiv 检索（原始 JSON）
```bash
node litmesh.mjs search_arxiv '{"query":"attention mechanism","max_results":2}'
```
真实输出节选：
```json
{ "source":"arxiv", "query":"attention mechanism", "total":337313,
  "papers":[ { "id":"2002.00741",
    "title":"Déjà vu: A Contextualized Temporal Attention Mechanism for Sequential Recommendation",
    "authors":["Jibang Wu","Renqin Cai","Hongning Wang"], "year":2020,
    "url":"https://arxiv.org/abs/2002.00741" } ] }
```
✅ 稳定性**高**（偶发瞬时抖动，重试即好）。

### 案例 3 · 自动引文 auto_cite（标注 + IEEE + BibTeX）
```bash
node litmesh.mjs auto_cite '{"text":"Attention mechanisms have become an integral part of compelling sequence modeling and transduction models in various tasks in recent years. The Transformer architecture introduced by Vaswani et al. relies entirely on self-attention and has been shown to be effective for machine translation.","style":"ieee"}'
```
真实输出节选（免 Key 模式，走本地断句 + 免费 API 关键词匹配）：
```json
{ "annotatedText":"... [1] The Transformer architecture introduced by Vaswani et al. [2] ...",
  "references":[ {"number":1,"formatted":"[1] E. Peterson and P. Kaur, \"Antibiotic Resistance ...\", Frontiers in Microbiology, 2018.","relevanceScore":0.39} ],
  "bibtex":"@article{ref1,\n  title = {Antibiotic Resistance Mechanisms ...}\n ...",
  "stats":{ "citationCount":4, "searchCount":13, "processingTime":103.84 } }
```
✅ 稳定性**高**（匹配精度取决于文本规范性，实体越明确越好）。

### 案例 4 · 统一跨平台检索 search_papers（优雅降级）
```bash
node litmesh.mjs search_papers '{"query":"graph neural network","sources":["semantic-scholar","pubmed","arxiv"],"max_results":2}'
```
当 Semantic Scholar 匿名限流（HTTP 429）时**不中断**，保留其余来源并附 warning：
```json
{ "total":30,
  "perSource":[
    {"source":"semantic-scholar","count":0,"error":"HTTP 429: Too Many Requests (after 3 attempts)"},
    {"source":"pubmed","count":10,"total":13689},
    {"source":"arxiv","count":10,"total":485822} ],
  "warning":"Semantic Scholar: ... HTTP 429 ..." }
```
✅ 稳定性**高**；只用 `sources:["pubmed","arxiv"]` 时完全无警告。

### 案例 5 · arXiv 全文抽取 read_arxiv_paper

✅ 稳定性**高**。

## 六、配置自定义（三平台互不冲突）

所有配置**只走环境变量**，可按平台各自设置，互不污染：

| 变量 | 默认值 | 作用 | 设置示例（Windows PowerShell） |
| --- | --- | --- | --- |
| `LITMESH_MODE` | `direct` | 运行模式（当前仅 `direct` 免 Key 可用） | `$env:LITMESH_MODE="direct"` |
| `SEMANTIC_SCHOLAR_API_KEY` | 空 | 提高 Semantic Scholar 匿名限流额度（可选） | `$env:SEMANTIC_SCHOLAR_API_KEY="你的Key"` |
| `LITMESH_TIMEOUT_MS` | 30000 | 单次请求超时（毫秒） | `$env:LITMESH_TIMEOUT_MS=60000` |

> 互不冲突说明：WorkBuddy 可在技能目录的 `.env` / 启动环境设；Claude Code 可在终端 session 设；
> Codex 可在其运行环境设。三者读取的是**各自进程的环境变量**，互不影响，也不会写回同一份配置文件。

## 七、常见问题（排错）

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `node litmesh.mjs --list` 报错找不到模块 | 未 `npm install` | 进入目录执行 `npm install` |
| Semantic Scholar 工具返回 HTTP 429 | 匿名限流 | 等几秒重试，或设 `SEMANTIC_SCHOLAR_API_KEY` |
| `search_papers` 仅返回部分来源 | 某来源 429 | 属正常降级；去掉该来源或设 Key |
| arXiv 偶发超时 | 瞬时抖动 | 重试即可（默认 3 次重试） |
| WorkBuddy 没识别技能 | SKILL.md 缺 `agent_created:true` | 确认未改动该字段；重开对话 |
| Codex 不读指令 | 未在 litmesh/ 目录启动 | 在目录内运行 `codex`，或复制 `codex.md` 到 `~/.codex/` |
